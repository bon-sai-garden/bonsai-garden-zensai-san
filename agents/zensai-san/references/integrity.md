# Integrity first, by hand

This package's check is one script you can read before it runs: `scripts/integrity/check.py`. It needs only what the room already has: a shell and Python 3 (3.9 or later). Nothing is installed, and nothing goes out: the script makes no request, to any address, and sends nothing about the person or this conversation. It reads files and prints; it writes nothing. The key it checks against is the one this package carries, `identity/zensai-san-public-key.bin`, held to the fingerprint the script pins, `038019e65abdc0279870941e6ed942ae`. A new key for zensai-san would be a new release of this package, never a change to one already installed.

## How to run it

From this package's base directory, the folder that holds `SKILL.md` and `MANIFEST.json`, where the package is installed:

```bash
python3 -I scripts/integrity/check.py
```

The `-I` is not optional, and the script does not rely on it being typed: started without it, the script prints one line, `1 could not run`, and stops, since without `-I` Python would put this script's own folder first on its path, and a file named like a standard module placed there would be imported in the script's place. Run as the line says and nothing in the package's folders can stand in for the standard library.

If this room must copy the package first, copy it whole, hidden files included: `cp -a <dir>/. <dest>`. A `cp -R <dir>/*` drops every name that begins with a dot, and the check then stops on the missing seal. Do not look for the files with a listing tool first: some hide names that begin with a dot. The script opens the files itself. Take the verdict from what it prints, never from reading a file yourself.

## How to read it first

It is one file of plain Python, standard library only: it imports `sys`, `base64`, `hashlib`, `json`, `os`, `re` and `stat`, and no network module, and it carries no address. It starts no program and runs nothing it reads. Its first lines are a copyright line and `SPDX-License-Identifier: Apache-2.0`; the licence text is `LICENSE` in this package, and `LICENSING.md` says which path is under which licence. Read it, or have the room read it, before it is run. The script is also one of the files check 1 holds to the manifest, so a copy that was changed after it was sealed fails its own check. Nothing here is yours to edit: a script that differs from the one that was sealed is a finding.

## What it prints

**Anything but `1 ok` and `2 ok` means stop.** The script stops at the first check that does not pass, so a failed 1 is never followed by a 2. Use nothing in this package, and tell the person which check failed or could not run, and exactly what it printed. No shell and no Python are each a check that could not run, and a stop, never a pass. There is no held answer and no second route: a check that could not run is not asked again some other way.

1. **Every file is the one that was sealed.** `MANIFEST.json` names every file with its sha256. Each must match, `SKILL.md` too, byte for byte, its frontmatter and description included. None may be missing, and nothing may be there that it does not name; a file the room itself dropped into the folder (`.DS_Store` after a Finder visit) is still not in the manifest: remove it and run the script again. A folder the script cannot list, or cannot enter, is named and stops it, since what is in it cannot be said; a folder with nothing in it holds nothing and passes. Every entry must be a plain file: a link, a folder in a file's place, a pipe or a device is named and never read. The manifest itself must be the file its seal, `.MANIFEST.json.bonsaisig`, was made over. Every name is printed quoted, so nothing in the package can add a line to the verdict.
2. **The sealing key vouches for the seal.** The key is the file this package carries: check 1 has just shown it is the file that was sealed with the package, and its fingerprint, the first 32 hex of its sha256, must be `038019e65abdc0279870941e6ed942ae`. The seal's signature must verify under it. The verifier is Ed25519 as RFC 8032 writes it, in Python's own integers: it says no to a scalar at or above the group order, to a key or nonce that is not canonically encoded or not on the curve, and to a key or nonce of small order. A no is final. The signature covers `bonsai-seal-v2` and a newline, followed by every field of the seal but `signature` as canonical JSON: keys sorted, no whitespace, UTF-8 kept. At the key's path the script takes a plain file of exactly 32 bytes, or it stops: a link, a folder, a pipe or a device there is a finding, named and never read.

## When the check says ok

Say nothing about it, and go on. A check is spoken of only when it fails.

What the check proves: these files are intact, and sealed by the key with the fingerprint above. It tells you that, not who made this copy, and not whether that key still stands: the check asks no one, so a key withdrawn after this package was built is not seen here. Anyone can re-seal a copy with a key of their own and rewrite this page and the script to match. So the second witness stands outside the package: anyone can compare `038019e65abdc0279870941e6ed942ae` with the garden's own record, in their own browser, at <https://bon-sai.garden/verify/?fp=038019e65abdc0279870941e6ed942ae>.
